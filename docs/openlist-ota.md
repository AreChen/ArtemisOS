# ArtemisOS 15：OpenList 更新通道

> **历史协议说明，已被替代。** 2026-11-12 用户决定采用 `/d/` → 天翼云 HTTPS 直连，不做旧更新器迁移，也不启用全局代理。当前实现、命令与验证见 [直连 OTA](openlist-direct-ota.md)。下文的分享、ShareId、连接组件及 HTTP 测试命令不要用于新版本。

这条通道使用 OpenList 保存已签名的静态更新文件。Windows 端现有更新程序负责下载、验证、应用和中断恢复；Android 内的“系统更新”界面是用户入口。它按变化文件下载完整文件，不是 Android `update_engine` 分区 OTA，也不是二进制差分。更新不会主动清除模拟器实例数据。当前候选 `system.img` 的逻辑长度约 3.33 GiB，若直接作为变化文件发布，客户端将下载完整的 3.33 GiB，可能比压缩后的完整安装包还大；因此本次小版本试运行不等于已解决系统镜像的高效增量升级。

## 接入与权限

兼容性要求：现有 1.0.x 更新器不跟随 HTTP 重定向，原分享地址必须直接返回 HTTP 200 文件内容。仅在浏览器能下载、或使用自动跳转的下载工具验签成功，都不能证明旧客户端可用。2026-11-12 曾实测 OpenList 返回 302 跳到天翼云，旧客户端因读取到跳转页而无法解析签名；发布器因此中止。可由管理员开启 [全局“强制代理分享文件链接”](https://doc.oplist.org/configuration/global#force-proxy-sharing-files)，但它会让所有分享下载经过服务器并占用带宽。只调整 OTA 的存储或反向代理也是部署选择，仍需管理员操作并保证原分享 URL 不变。

发布前必须用冻结旧 `core.ps1` 的 `Get-UpdateOffer` 和不跟随跳转的匿名对象读取进行验证；不能为绕过部署故障而关闭签名、旧哈希或路径校验。1.0.7 的逐版本升级与待发布状态见 [发行记录](history/release-1.0.7-display-recovery.md)。

- OpenList 账户只用于发布。发布脚本交互式读取凭据；不能把密码、令牌或签名私钥放入安装包、仓库、命令行历史或客户端配置。
- 为更新仓库单独创建只读分享，仅分享该目录。当前部署使用 `https://<host>/sd/<share-id>/?d`；客户端对每个文件请求带上 `?d`，由 OpenList 直接转发文件，不跟随跳转。分享地址是读取凭证，拿到地址的人能够下载其中的文件，因此不要放入其他私有资料。
- 自建域名和 HTTPS 证书需要在用户电脑上有效。`?d` 会消耗 OpenList 服务的网络带宽；正式使用前应评估服务器带宽、配额、可用性以及大文件传输和断点需求。
- 客户端使用**有签名的同版本空清单**确认“没有更新”；清单缺失（包括 HTTP 404）及其他服务器错误都作为检查失败，不能误报没有更新。发布脚本默认生成目标版本的签名空清单，普通静态服务器和 OpenList 均须提供它。
- 仓库中的对象以 SHA-256 命名。客户端验证签名、目标路径、已安装文件的基线哈希、下载长度和哈希；任何不匹配都会停止安装。

## 现有安装的首次切换

旧版客户端不认识 OpenList 的 `?d` 分享地址，必须先安装一次更新连接组件。`bootstrap-openlist.iss` 目前只接受使用项目现有公钥的 0.3.4 安装，会备份原来的更新程序和地址，再更新连接程序与服务器地址；它不改变版本号或虚拟机数据。用户应先关闭模拟器，安装后重新启动。组件构建时通过 `OpenListServerFile` 指定含只读分享地址的文本文件，不将地址硬编码在源码里。

已安装的 0.3.4 同版本可能包含不同的系统镜像。试运行的 0.3.4 → 0.3.5 清单仅修改版本文件，适用于这两种镜像基线，并不会缩小已安装的镜像；新构建的 0.3.5 试用安装包还可能包含较新的启动与初始化脚本。因此同为 0.3.5 的安装也可能拥有不同的镜像及脚本内容。后续若要更新这些文件，必须先识别实际基线并设计对应的版本和补丁，不能仅凭版本号假定文件完全相同。

0.3.6 是全新安装版本，包含经过独立验证的精简镜像和 Emulator 37.3.6；不提供 0.3.5 到 0.3.6 的升级或数据迁移。不能发布仅修改版本号的旧版升级清单来冒充完整升级。0.3.6 的服务端仅有本版本已签名的“没有更新”标记，不包含镜像或运行时。后续若发布更新，要基于实际的 0.3.6 安装内容生成并验证更新，不能只改版本号。

仅为新的独立安装版本准备并发布“没有更新”标记时，使用下面的命令；这不会读取旧版清单或上传更新对象：

```powershell
.\tools\New-UpdateSentinel.ps1 -TargetRoot <新版目录> -Repository <本地标记仓库>
$credential = Get-Credential
.\tools\Publish-OpenList.ps1 -Repository <本地标记仓库> -SentinelOnly `
  -TargetVersion 0.3.6 -RemoteRoot /ota -ShareId <只读分享 ID> -Credential $credential
$credential = $null
```

## 1.0.4 运行时补丁

1.0.3 → 1.0.4 的签名补丁仅包含 Windows 运行时和启动管理，117 个去重对象，共 598,759,355 字节；不上传 Android 系统镜像。两种历史 launcher 由共同 VBS 入口进入已签名迁移层，再以明确旧哈希和可恢复事务归一。用户配置、已装应用和 AVD 不属于更新目标；软件模式自动使用 ANGLE → Vulkan → SwiftShader，硬件选择保留。

完整安装与 OTA 的 1.0.4 基线分别保存在 `releases/1.0.4`、`releases/1.0.4-ota`。后续发布必须比较所更新路径的实际内容，不能仅依赖同版本号。构建、真实旧客户端升级、Android 启动证据和服务器发布状态见 [1.0.4 发布记录](history/release-1.0.4-modern-vulkan.md)。

## 构建和发布

1. 使用不可变的旧版和新版目录，从正式签名密钥生成本地更新仓库。默认会生成目标版本的签名空清单。例如：

   ```powershell
   .\tools\Publish-Update.ps1 -BaseRoot <旧版目录> -TargetRoot <新版目录> `
     -Repository <本地更新仓库> -PublishNoUpdateSentinel
   ```

2. 检查变化文件、基线和说明后，使用权限受限的 OpenList 账户发布。分享应已存在，且只包含指定的更新目录。

   ```powershell
   $credential = Get-Credential
   .\tools\Publish-OpenList.ps1 -Repository <本地更新仓库> `
     -FromVersion 0.3.4 -TargetVersion 0.3.5 -RemoteRoot /ota `
     -ShareId <只读分享 ID> -Credential $credential
   $credential = $null
   ```

   发布脚本会校验本地签名和对象哈希，先上传对象与目标版本的无更新标记，最后上传旧版到新版的清单，并匿名读回校验。相同内容可在中断后重试；遇到不同内容的目标版本或已有的其他更新时停止。清单和签名是两个文件，服务器没有原子发布事务，切换过程中短暂的签名不一致会让检查失败，重试即可，客户端不会安装未经验证的文件。请保证同时只有一个发布者。

3. 用独立安装目录检查更新、下载和应用；验证目标版本显示“没有更新”、旧数据不变，再向用户提供。

新安装包可以在编译 `installer.iss` 时通过 `OpenListServerFile` 提供默认地址；已有用户的个人服务器配置不会因覆盖安装被直接替换。现有安装用户使用上面的连接组件完成首次切换。

## 待解决

- 当前机制没有镜像分区级 OTA、压缩对象、差分包、断点续传、并发发布锁或密钥轮换。系统镜像正式更新前需要针对实际镜像基线设计压缩/差分和可靠回退，并验证磁盘空间与中断恢复。
- 一个来源版本对应一份清单；现存同版本不同镜像或脚本基线不能用同一基线哈希安全替换相应文件。
- 上传和分发 Google 系统镜像、模拟器二进制及其附带组件前仍需分别核实再分发许可；早期 0.3.x 小版本试运行未上传这些组件，1.0.4 运行时补丁的组件范围另见上述发布记录。保留随包许可文件不等于已确认所有再分发条件。
- [Google 的 SDK 索引](https://dl.google.com/android/repository/repository2-3.xml)将本版 Emulator 37.3.6 标记为 `android-sdk-preview-license`；预览许可第 3.3 条对复制、修改、再分发以及与其他软件组合设限，第三方许可另论。[Google APIs 镜像索引](https://dl.google.com/android/repository/sys-img/google_apis/sys-img2-3.xml)将本版 Android 35 x86_64 revision 9 镜像标记为 `android-sdk-license`；[SDK 条款](https://developer.android.com/studio/terms)第 3.4、3.5 条分别涉及限制和开源组件。内部开发使用本身不足以证明整包向其他用户分发已获授权，需结合具体场景和已有授权核查。上述是条款核对记录，不是法律结论。
