# ArtemisOS 原生显示前端

用户已要求将独立显示方式实现为正式前端，并要求现代、精致的外观。以下 UI 与技术细节是实现者在已授权方向内的选择，不是宣称用户逐项指定。

## 方案

采用 Windows 原生 C# / WinForms 品牌外壳，配合已在本机 Intel/NVIDIA Vulkan 上手测通过的独立 scrcpy 4.1 显示端。后台 Emulator 使用 `-no-window`。保持 scrcpy 为独立顶层窗口，通过 owner 关系与位置同步组合界面，不使用 `SetParent` 把它嵌成子控件，不修改它的 SDL 绘制后端。相比仅增加浮动侧栏，外壳提供统一标题、状态和窗口控制；相比新增浏览器界面，不引入浏览器运行时。

## 外观与功能

- 深色圆角外壳、细边框、少量蓝色强调；使用现有透明 ArtemisOS logo。
- 顶部：品牌、版本、实际渲染设备摘要、最小化与关闭。
- 中间：保持比例的 Android 画面；右侧分组图标按钮；底部显示连接和配置摘要。
- 首版按钮：返回、主页、多任务、音量加减、旋转、熄屏/唤醒、截图、安装 APK、导入文件、配置；更多菜单包含重启、退出。
- 启动、断线、异常和重新连接均有中文状态；按钮异步执行，避免阻塞窗口。
- 动画仅用于简短交互反馈，不持续绘制背景或使用视频背景。

## 运行与数据

- Windows x64，.NET Framework 4.8，使用 Windows 内置框架；不要求用户安装 SDK、Node 或 Python。
- 沿用现有 CPU/内存、分辨率、运营商和渲染偏好；不自动回退到 CPU 渲染，不删除 AVD 或 SD 卡。
- 新的 `launch.ps1 -ExternalDisplay` 只关闭模拟器原生窗口，保留原音频。scrcpy 禁止重复转发音频。
- 视频初始沿用已手测的 H.264、20 fps 上限、最长边1280、4Mbit/s、SDL direct3d。此设置仅影响显示流，不改变 Android 分辨率；高分辨率显示与额外编码 CPU 成本需单独验证。
- 每条 ADB 命令使用本安装自带 adb 和明确 serial。图形、系统、录屏等其他工具的 ADB server 不受影响。
- 单次会话由 GUID、安装根、backend PID/创建时间、serial 和日志路径标识，所有停止操作必须重新核对归属。
- 正常关闭应停止本前端显示端与所属后台；异常不无休止重启。重启复用原有 AVD 与偏好。

## 交付与更新

前端程序、显示运行时及资源放在 `update/frontend/**`，复用旧 OTA/recovery 白名单与递归安装。保留不同历史 VBS 入口；共同 root launch 默认委派前端，而 Headless 与 ExternalDisplay 跳过委派。

更新器在完成验证后，请求所属前端停止显示并退出，再独占停止 backend 和替换文件；前端进入更新状态时不与更新器争抢 backend。成功后沿原 VBS 恢复路径启动。前端不能用 kill-on-close Job 包住 updater 所在进程树。

本次先完成可运行本地集成和验证，尚不代表自动发布新版 OTA。第三方 DLL 必须携带相应许可、对应源码/构建来源说明；本机复用官方 WinGet 安装不等于已完成再分发审查。

## 验收

同一原 AVD 可用；渲染器确认为所选硬件；现代界面按钮有效；拖动、缩放、最小化、跨屏可用；关闭与重启无误杀其他实例/ADB server；启动与断线错误可见；升级自退出不杀 updater；截图与文件操作不损坏数据；CPU 和内存开销有实测记录。
