# ArtemisOS 1.0.0 SD 修复候选基线

- 旧基线：`releases/1.0.0`。
- 新基线：`releases/1.0.0-sd-fixed`。
- 二者包含相同的 444 个相对文件路径；新基线中的 `launch.ps1` 和 `使用说明.txt` 来自本次冻结的 `stage`，其余文件内容沿用旧基线。它们代表安装器的受管文件，不包含用户 `data`、卸载器、快捷方式或其他运行时生成文件。
- 425 个 SDK 文件逐一核对为相同卷和 NTFS 文件 ID 的硬链接；其他 19 个文件为独立副本。已检查非 SDK 文件的 SHA-256、SDK 原文件的大小及修改时间，并确认两个新版文件与冻结的 stage 对应文件的 SHA-256 一致。运营商覆盖文件、更新组件和许可证已与安装器输入核对一致。未重新哈希大型系统镜像。
- 本说明记录的是构建输入与基线的对应关系，不代表新安装包已经完成实际安装、Android 启动或 SD 卡挂载验收。应在新包编译完成后，使用隔离环境对实际安装结果进行验证。

## 必须保持 SDK 不可变

两个基线的 SDK 文件是硬链接，共享同一份底层文件；它们不是相互独立的备份。**不要原地编辑、替换内容、压缩、稀疏化、修改属性或让运行时向任一基线 SDK 写入**，否则可能同时改变两个基线，也会污染以后补丁的比较依据。需要处理 SDK 时，先复制为独立文件并确认不再共享文件 ID，再对副本操作。

旧基线和新基线的版本均显示为 `1.0.0`，但文件内容不同。现有 OTA 按版本选择更新，无法自动区分这两种基线；不要把它们当作同一个可自动识别的补丁来源。若旧包已分发，应为后续发行使用独立版本并分别核对来源文件哈希与迁移路径。

基线内包含构建时注入的更新服务配置，按内部敏感配置保管，不要直接公开整个基线。
