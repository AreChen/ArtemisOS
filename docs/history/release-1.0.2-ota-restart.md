# 1.0.2：修复 OTA 关闭后未重启

## 问题与原因

1.0.0 的更新入口在补丁下载并校验后提示将重启，但这不代表安装已完成。真实运行中，更新器先关闭 QEMU，然后发现 Android Emulator 启动了两个临时的 `emulator -kill <pid> -sleep 20` 清理进程。旧更新器把它们当成多个模拟器实例，拒绝继续安装；原模拟器已经关闭，因此也没有执行成功后的自动启动。

2026-11-03 在本机使用正式 1.0.0→1.0.1 签名更新重现了该问题，并捕获了关闭前后的进程。失败发生在写入产品文件之前；原 AVD 数据未清除。

## 修复与发布

- 1.0.2 更新器在已确认的模拟器退出后，最多等待 45 秒，直到该安装目录下的 QEMU、启动器和关闭清理进程都退出；身份不明确的进程或超时仍会中止更新。
- 更新入口改为提示正在关闭和安装，而非暗示安装已完成。失败时在 Windows 显示错误；如文件已安装但自动启动失败，提示手动启动。
- OpenList 已发布 1.0.1→1.0.2 的签名补丁和 1.0.2 无更新标记。补丁包含 `update/apply.ps1`、`update/bridge.ps1`、`version.ini`，不包含系统镜像或用户数据。
- 已经安装的 1.0.0/1.0.1 会先运行旧更新器，因此不能依赖 1.0.2 补丁自行绕过旧更新器问题。`ArtemisOS15-OTA-Repair-1.0.2.exe` 是一次性恢复工具：用户先关闭模拟器，工具检查旧更新组件，依次下载并校验签名补丁，完成后启动模拟器。它不会删除用户数据，也不会自动关闭运行中的实例。
- 恢复工具未进行 Windows Authenticode 代码签名；实际 OTA 补丁仍由现有公钥进行签名校验。工具本身的 SHA-256：`18765daa6f02d7be27ae692edfa46ee2e2b7c459c6f61a37a2e716f9630eca4e`。

## 验证

- 本机运行中通过修复后的更新器，从 1.0.1 升到 1.0.2，等待清理进程约 22 秒后自动重启；启动完成，SwiftShader 仍在使用，第三方应用列表与升级前一致。
- 等待逻辑的隔离测试覆盖清理进程、无关安装、无法识别进程和超时；原有进程身份、路径保护及数据保留测试通过。
- 使用实际修复工具和真实 OpenList 更新地址，在隔离目录分别测试两种 1.0.0 基线及 1.0.1；均升级到 1.0.2，启动前测试用用户数据和配置不变。首次启动时，1.0.0 升级用户的图形配置仍按 1.0.1 规则迁移到 SwiftShader。修改过的旧更新组件被拒绝。
- 已从 OpenList 匿名下载恢复工具并与本地产物核对大小及 SHA-256。用户实际机器与长时间运行稳定性尚未验证。
