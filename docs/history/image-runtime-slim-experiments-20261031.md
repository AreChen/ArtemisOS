# 独立镜像与运行时精简实验

## 范围与结论

本次比较以 `0.3.5-pilot` 为基线，在独立副本和独立 AVD 中进行。实验候选从系统镜像中删除“个人安全”和“数据恢复工具”，保留 64 位 ARM 转译、WebView、Google 服务、短信、电话、输入法等；紧急联络及设备迁移、恢复相关功能可能受到影响。保留文件和通过基础探针不代表所有应用和功能都已验证。现有安装和其用户数据没有作为实验目标。

源 `system.img` 与 SDK 构建输入有硬链接，不能原位修改。候选镜像的 SHA-256 是 `73eb28de6e94ebfb78f0dbf88988c21b39af13206fdabc7f0680e6a4fe213834`。文件系统自检通过，11 个关键 APK 在修改前后的 SHA-256 一致，6 个目标 APK/odex/vdex 路径已确认不存在。删除的文件逻辑大小合计 39,054,585 B，产品分区实际释放 38,838,272 B 的 ext4 块；**不能据此推算安装包或整机磁盘占用的变化**。生成过程及各项限制见[镜像实验说明](../../tools/image-lab/app-test-profile.md)。

安装器可显式启用实验性的 Qt 重复文件复用：先对 58 对资源文件及名称集合做校验，在编译期检查两侧 SHA-256，再将内容复用于两个安装路径，保留既有文件并让未列出的新增文件走原始通配规则。构建输入必须从生成清单到编译结束保持不变；编译前哈希检查不能阻止之后发生的修改。独立夹具验证了文件内容、已有文件保留和校验失败分支，详见[运行时实验说明](../../tools/runtime-lab/README.md)。

安装器中的稀疏镜像辅助脚本调整至固实压缩流开头，避免在镜像解压后为提取辅助脚本而回读压缩流。该调整不改变镜像内容，也不消除安装时先解压完整镜像所需的峰值空间；全新安装后的 NTFS 稀疏文件还需逐次校验内容。现有用户数据和已有镜像不会被此优化覆盖。

## 独立实例功能与资源采样

两组串行测试使用同一台 Windows 11 台式机、同一版 Windows Emulator、WHPX、软件渲染、720×1600、2 个虚拟 CPU、2.5 GiB 客体内存；机器有 32 个逻辑处理器和约 63.8 GiB 内存，测试时原有模拟器仍运行。每组仅测一次，采样包含启动、系统初始化和主动探针。测试程序在两次启动都传入 `-change-locale zh-CN`，因此会发生框架重启；实际产品已记录完成状态的后续启动不必传入此参数。`sys.boot_completed` 的耗时也不等于所有应用服务完全就绪的耗时。

基线的完整通过结果产生前，测试脚本曾因相对运行时路径、PowerShell 缺少压缩程序集、ADB 在语言初始化时短暂离线而中止，修复脚本后使用新目录重跑；候选在基线之后测试。之前的不完整运行和固定次序可能影响磁盘缓存，不能将这一次结果当作重复实验。

| 测量项 | 0.3.5 基线 | 实验候选 |
|---|---:|---:|
| 首次冷启动至 `sys.boot_completed` | 78.599 秒 | 50.350 秒 |
| 沿用同一实例数据的第二次冷启动 | 25.354 秒 | 22.692 秒 |
| QEMU 进程采样驻留内存峰值 | 3.596 GiB | 3.803 GiB |
| QEMU 进程采样私有提交内存峰值 | 4.129 GiB | 4.387 GiB |
| QEMU CPU 加权平均：一个逻辑核为 100% | 209.06% | 253.57% |
| 采样数 / 独立进程生命周期 | 22 / 2 | 20 / 2 |

驻留和私有提交内存是不同口径，不能相加；这些数值不包含其他 Emulator 进程、GPU/驱动及可能单独计量的虚拟化开销。CPU 以各采样窗口长度加权，窗口包含不同阶段的探针，样本时长和缓存条件并不完全一致。上述单次数据**不能证明候选更快或更省内存**，也不能代替低配置笔记本、多次交替采样和真实应用测试。原始采样方法见[测量说明](../../tools/benchmark-lab/README.md)。

基线和候选均通过两次冷启动、Settings 就绪、简体中文和 Asia/Shanghai 时区、DNS 与 TCP 443、x86_64 与 ARM64 JNI 探针、WebView 本地 HTML/JavaScript 和基础 Google 服务绑定。候选还确认两个目标包已从系统包列表中消失。这里不证明所有应用、完整 Google 服务、真实设备传感器或媒体编解码均可用。

## 打包与安装

基线 `0.3.5-pilot` 完整安装包为 1,232,523,021 B，SHA-256 为 `091e1fb478057407a0a985b0d48919bc6a09e1f4732d04b1753ec9956ed8fbbd`。采用 `lzma2/max` 的完整实验包为 **1,202,785,137 B（约 1.12 GiB）**，SHA-256 为 `1a53e97132895d11a1aac313e9cb7da7958f77665da31eb9834c39158f4712ee`，减少 29,737,884 B（约 28.36 MiB，2.41%）。相较原始的 1,928,750,267 B 安装包，实验包减少约 37.64%。这次差异同时包含系统组件删减、Qt 内容复用及压缩流布局调整，不能归因于其中某一项。Inno Setup 6.7.3 在此机器单次构建耗时约 639 秒；此数字不是其他机器的预期。

独立全新安装中，安装镜像与候选哈希一致，116 个 Qt 资源目标均与配对清单 SHA-256 一致；稀疏镜像逻辑大小为 3,576,692,736 B，Windows 报告的文件占用为 **2,273,443,840 B（约 2.12 GiB）**，比上一个试用版同口径的 2,312,044,544 B 少 38,600,704 B（约 36.81 MiB）。这只是 `system.img`，不是整个产品占用：首次启动并完成初始化后，独立安装目录的文件大小合计约 **6.33 GiB**，其中 SDK 约 3.00 GiB、实例数据约 3.32 GiB；应用、实例、快照及文件系统开销会改变总量。文件大小按 Windows 文件长度与稀疏/压缩大小统计，未包含所有文件系统开销。

独立安装日志记录的新包安装阶段为约 79.7 秒；之前基线的一次安装约 136.1 秒，两次缓存和负载并未控制，不能保证同样的总耗时差。日志直接显示旧包在提取完镜像后回读以恢复后续小文件约 44 秒，新包的辅助脚本在安装阶段之前提取，对应小文件安装约 3 毫秒。完整安装后，原有卸载登记与 7 个快捷方式的字节已恢复；独立实例冷启动、语言与网络初始化、简体中文和 Asia/Shanghai 时区通过，且能读取 OpenList 的签名当前版本标记。这次版本标记检查不等同于已经用该包完成一次系统镜像增量更新。

实验包仍复用现有 0.3.5 的安装标识和版本，默认路径可能指向已有安装，**不要将其作为正式版本直接覆盖现有环境，也未发布到 OpenList 更新通道**。原始本机采样和安装日志分别保存在 `build/benchmark-lab/` 与 `build/image-slim-exp/installer-evidence/`，构建目录不纳入 Git。

这里的 Google APIs 系统镜像及相关组件的再分发许可仍需核实，不能因实验通过就视为正式发布批准。现有 OpenList 更新机制按变化的整个文件传输；本实验不构成 Android 原生分区 OTA 或二进制差分更新。
