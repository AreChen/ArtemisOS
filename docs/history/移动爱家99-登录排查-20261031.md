# 移动爱家 99.0.0 登录排查

测试时间：2026-10-31，UTC+8。测试环境：ArtemisOS 15，Android 15 x86_64，应用包名 `com.cmri.universalapp`，应用版本 `99.0.0`。

## 已验证

- 应用可以进入登录页面，但用户使用手机号和短信验证码重试时仍提示“登录失败，请重新获取验证码[网络问题，请重试]”。
- 模拟器中的 AndroidWifi 已连接，系统时区为 Asia/Shanghai，系统时间与主机一致，应用的网络权限已授予。
- 测试时，模拟器可解析 `smsks1.cmpassport.com`、`www.baidu.com` 和 `example.com`。
- 从模拟器内测试 `smsks1.cmpassport.com:443`、`log1.cmpassport.com:9443`、`base.hjq.komect.com:443`：TCP 和 TLS 证书校验通过。用户重试时观察到应用进程与移动认证平台地址建立 TCP 连接；未捕获请求内容或服务端响应。
- 此电脑当前启动参数没有 `-dns-server 192.168.10.1`。当前测试未复现所述 DNS 解析故障，不能由此排除其他时刻或其他域名的偶发故障。
- 当前 99.0.0 安装包与此前的 10.12.0 安装包的签名证书摘要一致，且两个安装包的签名验证均通过。

## 与失败同时出现的日志

- `2026-10-31 17:41:38.980`：中国移动认证 SDK 的 `AuthnHelper.doCommonInit` 读取 SIMINFO 时出现 `java.lang.SecurityException: Access SIMINFO table from not phone/system UID`。模拟器显示的是虚拟运营商信息。该异常可能影响依赖本机 SIM 的认证，尚不能证明是本次短信验证码登录失败的直接原因。
- `2026-10-31 17:41:40.437`：`java.lang.NumberFormatException`；`CommonUtil.formatLoginErrorCode` 试图把“网络问题，请重试”解析成数字，调用链经过 `LoginFragment.onLoginFail` 和 `ActionManager$h.onError`。这是登录失败后的错误处理异常，原始登录失败原因尚未确定。
