# ArtemisOS 与雷电模拟器系统对比及镜像实验

记录时间：2026-10-31。本记录比较的是本机正在使用的两个实例，配置和后台负载不同，不能据此判断哪一方运行更快或更省内存。

## 系统参数

| 项目 | 本机雷电模拟器 | 本机 ArtemisOS 15 | 对 APP 测试的意义 |
| --- | --- | --- | --- |
| Android / API | Android 14 / 34 | Android 15 / 35 | 系统版本不同时，同一 APP 的权限、后台限制和兼容行为可能不同。 |
| 当前虚拟 CPU / 内存 | 6 核 / 约 5.8 GiB 可见内存 | 4 核 / 约 3.8 GiB 可见内存 | 这是各自实例的当前配置，不是软件性能对比。 |
| 当前显示 | 1920×1080，280 dpi，显示模式 120 Hz | 720×1600，320 dpi，显示模式 60 Hz | 分辨率、密度和刷新率都会影响渲染负载；比较时需要先统一。显示模式也不是实测帧率。 |
| 声明的 ABI | x86_64、arm64-v8a、x86、armeabi-v7a、armeabi | x86_64、arm64-v8a | 当前 ArtemisOS 不能覆盖只含 32 位原生库的 APP。64 位 ARM 支持依靠现有翻译组件，并非所有 APP 都已验证。 |
| 原生翻译组件 | `libhoudini.so` | `libndk_translation.so` | 只说明组件和 ABI 声明不同，不代表可直接互换组件。 |
| 图形 | 当前实例报告 Adreno / OpenGL ES 3.1 | 当前实例报告 Android Emulator OpenGL ES Translator / OpenGL ES 3.1 | 图形属性是模拟器报告值，不能单凭名称推断兼容性或性能。 |
| 安全补丁标识 | 2024-02-05 | 2024-09-05 | 版本标识可用于重现测试环境，不能单独证明系统或 APP 的安全状态。 |
| 构建类型 | `user`，`ro.debuggable=0` | `userdebug`，`ro.debuggable=1` | 测试涉及调试、设备完整性或反作弊时应记录此差异；这些属性不能单独证明 APP 是否可用。 |
| 地区 | 简体中文、Asia/Shanghai | 简体中文、Asia/Shanghai | 两台实例当前一致。 |
| 模拟移动网络 | 界面 / 属性报告中国移动、LTE | 已安装实例报告 T-Mobile、HSPA | 中国移动、电信、联通切换已经写入项目源码；本次比较的已安装实例尚未应用该源码。模拟运营商信息不等于接入真实蜂窝网络。 |
| 传感器和 NFC 特性声明 | 声明了 NFC、计步、折叠角度等特性 | 这些特性未出现在本机实例声明中 | 特性声明不等于硬件功能可用；需要逐项实际测试后再考虑是否支持。 |

本机 ArtemisOS 的 Android Emulator 是 37.3.4，`-accel-check` 检测到 WHPX 可用。官方说明将虚拟机 CPU 加速和 GPU 渲染加速区分开：没有可用 GPU 时可以尝试软件渲染，但软件渲染的运行成本和画面兼容性需要实际测试。

## 镜像空间试验

原始 `google_apis/x86_64/system.img` 为 3,576,692,736 字节。它包含 GPT 和动态分区；本次没有改动原文件，而是把其中的 `product` 分区复制到工作区 `build/image-lab`，只在独立副本上试验。

移除了 `Drive`、`PrebuiltGmail`、`Maps`、`YouTube`、`YouTubeMusicPrebuilt` 和 `Photos` 的 APK 及其预编译文件，保留 Google Play 服务、WebView、输入法、系统组件和 ARM64 翻译器。原始 ext4 分区使用 `shared_blocks` 去重：普通的逐文件删除可能错误释放其他文件共用的数据块。实验先解除目标文件的目录链接并清除对应 inode，使用 `e2fsck` 重建分配信息，再将确认空闲的块清零；最后 `e2fsck -fn` 返回干净。这个过程只适用于本次识别过的镜像结构，不应直接套用到其他版本。

`tools/image-lab/prepare-product-removal.py` 可在 WSL 中对已分离的原始 product 分区做只读校验，并为这个精确版本生成实验命令文件；它不修改镜像，也不自动打包。必须在独立副本上执行生成的命令并完成文件系统修复，不能对现有安装或与其硬链接的镜像动手。此工具尚不是完整的镜像构建流水线。

| 指标 | 原始 product 分区 | 实验 product 分区 |
| --- | ---: | ---: |
| 分区文件长度 | 2,144,882,688 B | 2,144,882,688 B |
| ext4 已用块 | 513,818 × 4096 B | 351,534 × 4096 B |
| `xz -0 -T4` LZMA2 压缩流 | 916,753,296 B | 681,722,896 B |

分区内部释放约 634 MiB；上述压缩流减小 235,030,400 B，约 224 MiB。原始磁盘镜像长度没有改变，因此这不是安装后磁盘占用直接减少 634 MiB 的证明。该压缩测试只针对 product 分区，实际安装程序使用 Inno Setup 的 `lzma2/fast` 和固实压缩，最终安装包的体积需要完整构建后才能确定。

实验镜像在 `build/image-lab/sysimg/system.img`，没有合入安装程序、更新包或当前已安装的模拟器。原产品提供“取消精简后恢复应用”的配置；若最终采用物理删除，这一恢复行为必须重新设计并验证，不能沿用原来的提示。

### 独立启动验证

- 用单独的测试 AVD 启动实验镜像，配置 2 核、2 GiB 内存、SwiftShader 软件渲染；系统启动完成，设置应用可以启动。宿主仍启用了 WHPX 虚拟化加速；这不等于已在低配置实体电脑上完成性能验证。
- 挂载后的 `product` 分区中，预期移除的 18 个文件均已消失，其余 438 个普通文件的 SHA-256 与原镜像逐一一致；Google Play 服务、WebView 和输入法仍出现在包列表中，但这还不构成它们的完整功能测试。
- 使用项目中的 `tests/arm64-jni-probe/Run-Probe.ps1` 构建独立测试 APP，只打入 `arm64-v8a` 的 JNI 动态库；安装启动后，原生函数返回预期值 `37042`。同时确认 `libndk_translation.so` 存在。它证明这项基础 ARM64 转译用例可用，不代表所有 ARM64 APP 都已验证。
- 系统报告 SELinux `Enforcing`、verity 已启用，且 `system-verity` 映射存在。不能由此推断所有分区都受到同样的校验，也不能代替后续的完整启动链与升级测试。

## 值得优先处理的后续工作

1. 在真实 8 GiB 内存、集成显卡或没有可用硬件图形加速的电脑上测冷启动、空闲内存和普通 APP 操作；分别覆盖硬件和软件渲染，并记录崩溃、耗时及 CPU 使用率。
2. 建立统一测试集，在相同虚拟核数、内存、分辨率、刷新率和后台条件下比较启动、安装、网络、媒体播放与长时间运行，避免用不同配置直接下结论。
3. 按当前需求保留 64 位方案；暂不增加 32 位系统库或翻译组件。今后出现明确需求时再评估独立兼容环境。
4. 针对网络、SIM、摄像头、麦克风、位置和传感器做可操作的测试能力；只声明未经实现的硬件特性会干扰 APP 测试结果。
5. 对安装器内只用于其他客体 CPU 架构的 QEMU 可执行文件评估裁剪，同时保留 x86_64 图形/无界面运行程序及 Android 客体里的 ARM 翻译组件，验证后再考虑合入。
6. 在合入镜像或发布之前，验证新装、已有数据升级、回滚、启动完整性、网络、媒体、输入法、Google 服务以及常见 APP 的 ARM64 原生库。
