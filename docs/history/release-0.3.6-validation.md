# ArtemisOS 15 0.3.6：运行时与镜像验证

## 版本和来源

- 产品版本为 0.3.6；运行时为 Android Emulator **37.3.6.0 Canary**，build 16696583。它是预览版运行时，不应表述成 Google 的稳定版。
- Google 官方 Windows x86_64 运行时下载文件 `emulator-windows_x64-16696583.zip` 的 SHA-256 为 `20cac32f4606f289911cb472fd578ee7716dd163153849098c0de634847877bd`。下载地址及 SHA-1 来自 [Google SDK 官方索引](https://dl.google.com/android/repository/repository2-3.xml)；实际文件也验证了索引中的长度及 SHA-1。
- 系统基于 Google APIs Android 35 x86_64 revision 9 镜像的精简候选，并非从 AOSP 源码自行构建。`system.img` 的 SHA-256 为 `ab633cc0504a61c6006cd39d2b371dff8e341f0176e70384597692d7d90a2752`，逻辑长度为 3,576,692,736 字节。
- 打包 SDK 保留 x86_64 虚拟机后端，省略未使用的 aarch64、armel 和 i386 虚拟机后端；这与 Android 客户机中应用的 ABI 不是同一回事。ARM64 JNI 与 x86_64 JNI 均经过本机冒烟检查，但不代表全部 APK 兼容。
- 安装包 `ArtemisOS15-Offline-Installer-0.3.6.exe` 长度为 1,233,040,929 字节，SHA-256 为 `101f18c87cf652ab4eb3c62a06f03582100e6dc9e9efed23ad7c9df2d8dfc04f`；安装包未进行 Authenticode 签名。

## 隔离运行验证

在本机独立 AVD 使用 37.3.6、软件渲染和低配置进行两次冷启动。包管理器和设置 Activity、简体中文、上海时区、ARM64/x86_64 JNI、WebView 的本地 JavaScript、Google Play 服务基础绑定、DNS 解析和 443 端口连接均通过。结果记录在 `build/emu3736-pilot-evidence/test-results.json`；两次单机启动计时不作为性能基准。

首次启动时观察到 `system_server` 启动计数从 1 增加到 2；此前的未修改镜像对照也观察到计数变化，原因尚未确认。因此通过上述冒烟检查不能推断长期运行没有系统服务重启。

另外以产品生成的 SIM 配置和 37.3.6 在独立 AVD 验证了中国电信和中国联通：网络与 SIM 编号分别为 46003、46001，网络名称正确，SIM 状态为 LOADED。`gsm.sim.operator.alpha` 均为空；没有验证真实短信或蜂窝业务。记录位于 `build/sim-3736-20261101-evidence-v2/results.json`。中国移动名称在本机当前实例上检查通过。

图形预检中，自动模式选择 NVIDIA OpenGL 路径后发生一次 QEMU 进程崩溃，Windows 记录的故障模块为 `nvoglv64.dll`；当时另一模拟器和安装包压缩也在运行。随后关闭其他实例和压缩负载，在同一显卡驱动上单独使用 auto 冷启动并观察 66 秒，没有重现；此对照不足以确定崩溃根因。SwiftShader 独立冷启动并观察 68 秒也通过。新安装采用 auto，在本机实测会使用 NVIDIA 硬件加速；用户可在配置中选择硬件或其他模式，软件渲染可能增加 CPU 占用。记录位于 `build/gui-3736-5572-isolated/`。

本次验证不能说明所有 Windows 版本、显卡、完全无 GPU 的电脑、低性能笔记本或应用均已通过，也不证明真实手机传感器和 NFC 功能可用。

## 实际安装包与本机数据

使用安装包在隔离目录完成安装，核对系统镜像及安装后的 37.3.6 可执行文件、简体中文、UTC+8、网络初始化与 OpenList 已签名的同版本无更新标记，并完成独立冷启动。使用 NTFS 稀疏文件时，安装后系统镜像逻辑长度为 3,576,692,736 字节，实际分配 2,312,044,544 字节；不同文件系统可能不同。

实际安装内容（不含 `data` 和卸载器）已保存为 `releases/0.3.6`，共 444 个文件，逐文件核对 SHA-256，用作后续按文件更新的基线。服务配置文件是构建时注入的私有分享能力，不提交到 Git；后续新装包需要显式提供 `OpenListServerFile` 才能预配置同一更新服务。

`stage/version.ini` 与 `stage/sdk` 已对齐本发行版；为了保持精简 SDK 构建工具的输入要求，构建目录额外保留了从官方 37.3.6 原包校验的 6 个其他客户机架构 QEMU 程序，生成精简输入时会再次排除。生成检查已通过，先前 SDK 和版本文件保存在 `backups/`。

原实例停机后保留了完整数据备份，比较原始数据与备份后，在独立目录复制、校验数据盘及加密盘与缓存盘的 backing 链，再切换到新安装的 `data` 目录。原安装及其数据仍保留。新版使用继承的自动渲染设置成功启动，窗口显示 0.3.6，Android 报告中文及上海时区，保留 `com.cmri.universalapp` 99.0.0，DNS 解析和 TCP 443 冒烟检查通过；这不等于重新验证了应用登录状态或全部应用数据。旧 RAM 快照保留在备份中，未在新版加载。

## 更新与许可

0.3.6 是全新安装版本，不提供从 0.3.5 的自动升级或自动数据迁移。本机迁移是针对这台电脑单独完成的复制验证，不能推断其他安装均可直接迁移。OpenList 只发布本版本已签名的无更新标记；没有上传系统镜像或模拟器运行时。更新通道的基线要求和许可限制见 [OpenList 更新通道](../openlist-ota.md)。
